TrueSkate-AI — learning to skate from pixels

A personal research project on learning fine motor control from vision alone: an agent playing True Skate on unmodified physical iPhones, seeing only screen frames and acting only through touch.

Asher Noble
log started 2026-06
status in progress
no publication

01WHAT IT IS

I’m training a machine learning model to play True Skate on unmodified physical iPhones. It sees only screen frames and acts only through touch — no access to the game’s code.

The controls are continuous, the feedback is delayed, and the game reports a trick’s name on screen but nothing else.

My conjecture: I can’t assimilate the whole internet in a lifetime, and I can’t train a frontier LLM with <$1000 of compute — but I did master True Skate well within a lifetime, so it may be possible to train a machine learning model to play it on <$1000 of compute.

The long-term vision is a tendon-driven robotic hand tapping and swiping real glass (read section 04 for a thorough overview). I am currently experimenting with offline learning with the intention to translate the 2D trajectories inferred by the trained model into 3D trajectories taken by the fingers of the robotic hand.

03HOW IT WORKS

Six stages. The system started on CMA-ES — an evolutionary optimizer rewarded by the trick name read off-screen by Apple Vision OCR, which is what landed the 360 flips in section 05 — and is now built around two-stage behavioral cloning: it learns gestures from expert play instead of searching for them via RL.

01demonstrationsmy expert True Skate gameplay captured on via screen recording on my iPhone.
02gesture corpusa script performs random gestures via Appium + WebDriverAgent and collects the video frames they produce.
03trace extractora small U-Net is trained to predict the gestures that produced a given sequence of video frames for the corpus created in step 02.
04strokesper-frame touch points fit into discrete curved drags (waypoints, duration, easing, curvature), normalized across three screen sizes.
05policya transformer (or another architecture) takes recent frames plus recent gestures and predicts the next gesture.
06inferencegestures are inferred and translated from 2D cartesian trajectories to 3D trajectories executed by the robotic hand on the 2D iPhone screen.

An earlier CMA-ES baseline and a collapsed PPO + HER attempt taught me what this noisy real-time setting could and couldn’t give back.

04THE HAND

Almost every robotic hand is built to grip and are thus optimised for high torque. Mine needs relatively little torque but requires very high speed, acceleration and precision. I’m building the open-source ORCA hand with gimbal motors instead of servos and the intention of making hardware modifications until it is optimised for virtual finger skating.

The first build is a two-finger scaffold (index + middle) to prove the module and the control loop before scaling to five.

06ROADMAP

Two tracks, neither committed to a date. This is intent, not a schedule.

Track A · the agent (software):

A1per-trick masteryreliable, repeatable landings for individual tricks across the 36-trick flatground set — currently in progress.
A2one policya single skill-conditioned network that performs any trick on command.
A3style imitationan agent that strings tricks into full park lines that look like how I actually skate.

Track B · the hand (hardware):

B1two-finger modulecurl and splay on index and middle, proving the mechanism and the control loop before scaling up — currently in progress.
B2five-finger handscaling the curl-and-splay module to a complete tendon-driven hand.
B3physical playa left hand holding the iPhone and a right hand finger-skating on real glass, finished cleanly enough to sit on a podium on long-term display.
