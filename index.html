trueskate-ai — learning to skate from pixels

A personal research project on learning fine motor control from vision alone: an agent playing True Skate on unmodified physical iPhones, seeing only screen frames and acting only through touch.

Asher Noble
log started 2026-06
status in progress
no publication

01WHAT IT IS

I’m teaching an agent to play True Skate on unmodified physical iPhones. It sees only screen frames and acts only through touch — no simulator, no access to the game’s code, no reward injected into the process.

That framing is the hard way, on purpose. The controls are continuous, the feedback is delayed, and the game reports a trick’s name on screen but nothing else.

My conjecture: I can’t assimilate the whole internet in a lifetime, and I can’t train a frontier model on consumer hardware — but I did master True Skate well within one. So it may be possible to train an agent to play it on consumer-grade hardware too.

The endgame actuator is a tendon-driven robotic hand tapping and swiping real glass, not a script poking an API — section 04 covers it.

03HOW IT WORKS

Five stages. Everything between capture and touch is replaceable; the only interface between stages is a frame buffer and a stream of touch events. The system started on CMA-ES — an evolutionary optimizer rewarded by the trick name read off-screen by Apple Vision OCR, which is what landed the 360 flips in section 05 — and is now built around two-stage behavioral cloning: it learns gestures from expert play instead of searching for them.

01demonstrationsexpert True Skate gameplay captured on real iPhones; the only data the policy learns from.
02trace extractora small U-Net reads each frame and finds the finger on the glass, self-labeled from the agent’s own known gestures.
03strokesper-frame touch points fit into discrete curved drags (waypoints, duration, easing, curvature), normalized across three screen sizes.
04policya transformer takes recent frames plus the last few strokes and predicts the next stroke.
05actuationstrokes executed on physical iPhones via Appium + WebDriverAgent; a physical hand is in design.

An earlier CMA-ES baseline and a collapsed PPO + HER attempt taught me what this noisy real-time setting could and couldn’t give back.

04THE HAND

Almost every robotic hand is built to grip. This one needs the opposite — speed and human-like motion under no load. I’m folding the best-suited features of three open-source hands — ORCA, HRI, Ruka-v2 — into my own.

Each finger gets a tendon-driven curl plus base splay, roughly two to three degrees of freedom, with capacitive fingertips gated electronically so every tap registers. The first build is a two-finger scaffold (index + middle) to prove the module and the control loop before scaling to five.

06ROADMAP

Two tracks, neither committed to a date. This is intent, not a schedule.

Track A · the agent (software):

A1per-trick masteryreliable, repeatable landings for individual tricks across the 36-trick flatground set — currently in progress.
A2one policya single skill-conditioned network that performs any trick on command.
A3style imitationan agent that strings tricks into full park lines that look like how I actually skate.

Track B · the hand (hardware):

B1two-finger modulecurl and splay on index and middle, proving the mechanism and the control loop before scaling up — currently in progress.
B2five-finger handscaling the curl-and-splay module to a complete tendon-driven hand.
B3physical playa left hand holding the iPhone and a right hand finger-skating on real glass, finished cleanly enough to sit on a podium on long-term display.
